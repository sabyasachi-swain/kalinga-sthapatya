# Kalinga Sthapatya (କଳିଙ୍ଗ ସ୍ଥାପତ୍ୟ)

Static educational website about Odisha temple architecture for families and kids.
Vanilla HTML/CSS/JS + JSON, hosted on GitHub Pages.

- **New session? Start with `HANDOFF.md`.**
- What to build: `implementation_plan.md` · How it is built: `EXECUTION_PLAN.md` · Progress: `BUILD_STATUS.md`
- Research leads: `Odisha Temple Archtecture research.md` — leads only, **never a citation**.
- Drive the build with `/kalinga-orchestrator <phase>`; work is delegated to the `kalinga-*` agents.

## Rules that always apply

1. **Facts live only in `data/*.json` as cited claim objects.** HTML/JS never hardcode dates, heights,
   dynasties, attributions or meanings. Unverified → `null`, rendered as "Not yet verified".
2. **Accepted sources only:** academic books, peer-reviewed papers, edited primary texts, epigraphy, ASI,
   UNESCO/ICOMOS, government archaeology docs. No Wikipedia, blogs, news, tourism sites, AI output.
   Never invent a quote, URL, page number or measurement. See the `kalinga-content-policy` skill.
3. **`data/` content changes only via `node scripts/merge-staged.mjs`** (main session). Never edit
   `scripts/validate-content.mjs` or `scripts/merge-staged.mjs` to make content pass — ask the human.
4. **Visuals are generated by the human with Gemini.** Claude writes briefs in
   `visual-briefs/VISUAL_REQUIREMENTS.md` and shows placeholders; it never draws or sources substitute art.
5. **Accessibility and relative URLs are part of done.** See the `kalinga-design-system` skill.
6. Outward actions (git push, creating repos, enabling Pages, installing packages) need explicit approval each time.

## Commands

- Validate content: `node scripts/validate-content.mjs` (`--strict` before launch, `--staged <file>` for fragments)
- Merge fact-checked data: `node scripts/merge-staged.mjs [--dry-run] research/staged/<topic>.json`
- Local preview: `npx serve .` or `python -m http.server 8000` (JSON fetch fails on file://)
