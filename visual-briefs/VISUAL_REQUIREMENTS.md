# Kalinga Sthapatya — Visual Requirements for Gemini

Every visual on the site is generated by you with Google Gemini. This file is the single list of
what to generate, how, and how each result will be checked. Claude agents keep it updated
(`kalinga-visual-brief-writer`) and never generate images themselves.

**Status legend:** `ready` = send now · `draft` = usable, will be refined after research (Phase 1V) ·
`hold` = wait: the fact behind it is not verified yet.

---

## 1. How to use this file

1. **Generate V-00 (style anchor) first.** Approve it, then attach it to every *recognizable*-style prompt.
   Once V-11 (hero) is approved, attach it to every *artistic*-style prompt.
2. For each brief: paste the **Global Style Block** for its style + the brief's prompt. Attach the listed
   reference photos (your own, public domain, or CC-licensed — note the source in `references/REFERENCES.md`).
3. Pick **Image mode** (Gemini image model) or **Code mode** (Gemini text model writing SVG) as the brief says.
4. Save the result to `visual-briefs/inbox/` using the exact file name given, e.g. `V-33_exploded-view.png`.
5. Tell Claude: `/kalinga-orchestrator phase-4`. The integrator checks every item on the brief's checklist
   and you approve (gate G4) before anything goes live. Rejected images get a regeneration note here.

**General delivery specs**
- Raster: PNG, the stated aspect ratio, longest side ≥ 2048 px (≥ 2400 px for heroes). Claude converts to WebP.
- SVG: one self-contained file, `viewBox` exactly as specified, no `width`/`height` attributes.
- **Never any text in images** — no letters, numbers, labels, signatures, watermarks, Odia script.
  All labels are added by the website as HTML (they stay accurate, accessible and translatable).

## 2. Global Style Blocks (paste at the start of prompts)

### 2a. Artistic style — landing hero, backgrounds, featured temple
> Style: warm, contemporary flat-vector editorial illustration with subtle paper-grain texture, inspired
> by Odisha's Kalinga temple architecture. Palette: laterite red #A0522D, deep sienna #8B4513, sandstone
> gold #C9A84C, khondalite brown-grey #6B5B4E, cream #FBF7F0, charcoal #1A1A1A, on a light cream sky.
> Soft morning light from the left (east). Clean silhouettes, calm balanced composition, generous empty
> space. Absolutely no text, letters, numbers, signatures, watermarks, frames or borders. No people,
> animals, vehicles, modern signage, power lines, or flags with writing.

### 2b. Recognizable style — temple pages, type cards, builder steps
> Style: detailed, architecturally accurate painted illustration (gouache/digital painting, not a photo),
> faithful to the attached reference photos in proportions, number of tiers, projections and silhouette.
> Natural stone colours: khondalite grey-brown and weathered ochre sandstone; laterite red-brown for
> platforms and compound walls. Soft morning light from the left (east), clear sky, light haze, gentle
> shadows. Clean uncluttered surroundings with a little lawn or paving. Sculptural carving reads as fine
> ornamental texture at this distance — no explicit figures. Absolutely no text, letters, numbers,
> signatures or watermarks. No people, animals, vehicles, modern signage, power lines, scaffolding,
> tourists, or flags with writing.

### 2c. Rendered style — exploded view
> Style: high-quality 3D architectural render of carved stone on a pure white background, soft studio
> lighting from the upper left, subtle contact shadows, realistic khondalite and laterite stone textures,
> precise edges, museum-model feel. Absolutely no text, labels, arrows, numbers or watermarks.

### 2d. Code mode (SVG) — prepend to every SVG prompt
> Output only one valid SVG document — no markdown fences, no explanation. Use exactly the viewBox given
> and no width/height attributes. No <text>, <image>, <script>, <style> blocks, filters, external
> references, or event attributes. Use fill/stroke "currentColor" unless told otherwise. Round coordinates
> to 1 decimal. Give groups exactly the ids listed. Keep paths simple (the file should be under 30 KB).
